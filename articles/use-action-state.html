React / Actions

useActionStateについて

作成日: 2026年6月2日

useActionStateは、フォーム送信やボタンクリックなどで実行するActionの結果を、Reactの状態として扱うためのHookです。非同期処理、送信中状態、直前の結果、エラー表示をひとまとまりに整理できます。

簡潔なQ&A

Q. useActionStateとは何？
A. Actionを実行し、その戻り値をコンポーネントの状態として保持するReact Hookです。送信中かどうかを表すisPendingも一緒に受け取れます。
Q. useStateやuseReducerと何が違う？
A. useStateは値を直接更新し、useReducerは純粋な状態遷移を表すのに向いています。useActionStateは、サーバー送信などの副作用を含む処理を実行し、その結果で状態を更新する場面に向いています。
Q. フォーム専用のHookなの？
A. フォームと相性がよいですが、フォーム専用ではありません。手動で呼ぶ場合はstartTransitionで包むか、<form action>のようなAction propに渡して使います。

基本の形

useActionStateは、Action関数、初期状態、必要に応じてpermalinkを受け取り、現在の状態、Actionを呼び出す関数、処理中フラグを返します。

import { useActionState } from "react";

const [state, dispatchAction, isPending] = useActionState(
  reducerAction,
  initialState,
);

Action関数は、前回の状態を第1引数として受け取ります。第2引数以降には、dispatchActionに渡した値や、フォーム送信時のFormDataが入ります。

何を解決するHookか

Reactアプリでは、送信処理の周辺に似た状態管理がよく出てきます。たとえば「送信中か」「成功したか」「バリデーションエラーは何か」「前回の入力結果をどう表示するか」といった状態です。

useActionStateを使うと、送信処理そのものをActionとして書き、その戻り値をUI表示用の状態にできます。これにより、非同期処理と結果表示の関係がコンポーネントの中で追いやすくなります。

フォームでの例

フォームのaction propにdispatchActionを渡すと、Reactが送信をActionとして扱います。この場合、React側でTransitionとして扱われるため、手動でstartTransitionを書く必要はありません。

import { useActionState } from "react";

type FormState = {
  message: string;
  error: string | null;
};

async function submitName(
  _previousState: FormState,
  formData: FormData,
): Promise<FormState> {
  const name = String(formData.get("name") ?? "").trim();

  if (!name) {
    return { message: "", error: "名前を入力してください。" };
  }

  await saveName(name);
  return { message: `${name}を保存しました。`, error: null };
}

export function NameForm() {
  const [state, formAction, isPending] = useActionState(submitName, {
    message: "",
    error: null,
  });

  return (
    <form action={formAction}>
      <input name="name" />
      <button disabled={isPending}>
        {isPending ? "保存中..." : "保存"}
      </button>
      {state.error && <p>{state.error}</p>}
      {state.message && <p>{state.message}</p>}
    </form>
  );
}

ポイントは、Actionが「成功・失敗を含む表示用の状態」を返していることです。想定内のバリデーションエラーはthrowせず、状態として返すとUIに出しやすくなります。

手動で呼ぶ場合

ボタンのonClickなどから直接dispatchActionを呼びたい場合は、startTransitionで包みます。これを忘れると、isPendingが期待通りに更新されないことがあります。

import { startTransition, useActionState } from "react";

function LikeButton({ postId }: { postId: string }) {
  const [, like, isPending] = useActionState(likePost, null);

  function handleClick() {
    startTransition(() => {
      like({ postId });
    });
  }

  return (
    <button disabled={isPending} onClick={handleClick}>
      {isPending ? "反映中..." : "いいね"}
    </button>
  );
}

useReducerとの違い

観点 useReducer useActionState
主な用途 ローカル状態の遷移を整理する。 副作用を伴うActionの結果を状態にする。
関数の性質 基本的に純粋なreducerとして書く。 非同期処理やサーバー送信を含められる。
pending状態 自分で管理する。 isPendingとして受け取れる。
フォーム連携 手動でonSubmitを書くことが多い。 <form action={formAction}>と自然に組み合わせられる。

エラー処理の考え方

入力ミスや在庫不足のように、UIで通常表示したいエラーはActionの戻り値として返します。一方、想定外の例外はthrowすると、Reactは近くのError Boundaryへ流します。

つまり、useActionStateでは「ユーザーに見せる業務上の失敗」と「アプリとしての例外」を分けて扱うと読みやすくなります。

Async Reactとの関係

useActionStateは、ReactがAction、Transition、Suspense、Error Boundaryなどで非同期UIを扱いやすくする流れの中にあるAPIです。送信中の状態をisPendingで扱い、Actionの結果を状態にし、必要ならError Boundaryへ例外を渡せます。

そのため、単なるフォーム便利Hookというより、「非同期の操作をReactのレンダリングモデルに乗せるためのHook」と捉えると理解しやすいです。

よくある注意点

  • Action関数の第1引数は前回の状態です。フォームのFormDataは第2引数になります。
  • 手動でdispatchActionを呼ぶ場合は、基本的にstartTransitionで包みます。
  • 複数回呼び出すと、ReactはActionを順番に処理します。連打時の体験が重要な場合はuseOptimisticとの併用も検討します。
  • 戻り値の型は初期状態と揃えます。TypeScriptでは状態の型を明示すると読みやすくなります。
  • Server Functionsと組み合わせる場合、状態や引数はシリアライズ可能な値にします。

要点

useActionStateは、非同期Actionの「実行」「結果」「送信中状態」をReactの状態としてまとめて扱うHookです。フォーム送信と特に相性がよく、想定内のエラーは状態として返し、想定外の例外はError Boundaryに任せる、という整理ができます。
