React RouterとTanStack Routerの違い

作成日: 2026年5月19日

React RouterはReact界隈の標準に近い実績あるルーターで、現在はFramework Modeによってフルスタック寄りの性質も持ちます。TanStack Routerは型安全性、検索パラメータ、TanStack Queryとの連携を強く意識した新しいルーターで、TanStack Startによってフレームワークとしても使えます。

簡潔なQ&A

Q. React RouterとTanStack Routerの一番大きな違いは？
A. React Routerは実績、互換性、フレームワークとしての安定感が強みです。TanStack Routerはルート、パラメータ、検索条件、リンク、ローダーを型安全に扱う体験が強みです。
Q. どちらもフレームワークとして使えるのか？
A. はい。React RouterはFramework Modeで、TanStack RouterはTanStack Startと組み合わせることで、ルーティングだけでなくデータ取得、SSR、フォーム処理、サーバー処理まで含む構成を取れます。
Q. ストア管理の観点ではどちらが優れている？
A. サーバーデータとURL状態を中心に考えるならTanStack Router + TanStack Queryの組み合わせが強力です。一方、React Routerはloader/action/revalidationにより、ルーター自身がネットワーク関連状態をかなり吸収してくれます。

比較の前提

React RouterもTanStack Routerも、単にURLとコンポーネントを対応させるだけのライブラリではなくなっています。データ取得、保留状態、エラー境界、フォーム送信、SSR、ファイルベースルーティングなどを扱えるため、アプリケーション設計全体に影響します。

ただし、思想は異なります。React RouterはRemix由来のWeb標準寄りのデータフローをReact Router本体に取り込み、TanStack Routerは型安全なルート定義とTanStackエコシステムとの組み合わせで開発体験を作ります。

React Routerの特徴

React Routerは長く使われてきたReactの代表的ルーティングライブラリです。現在はDeclarative、Data、Frameworkという複数のモードがあり、必要に応じて単純なSPAルーターからフルスタック寄りのフレームワークまで段階的に使えます。

優れている点

  • 採用実績が多く、学習資料や既存コードが豊富。
  • Framework Modeでは、ファイルベースのルート、loader、action、pending UI、SSRなどを扱える。
  • loader/action/useFetcher/revalidationにより、送信後の再読み込みや遷移中状態をルーターが管理しやすい。
  • Remixの考え方を引き継いでおり、フォーム送信やHTTP的なデータフローに強い。

注意点

型安全性は改善されていますが、TanStack Routerほど「ルートツリー全体から型が推論され、リンクや検索パラメータまで強く型付けされる」体験ではありません。また、サーバーデータのキャッシュやクライアント側の細かな状態管理は、用途によって外部ライブラリと組み合わせることになります。

TanStack Routerの特徴

TanStack Routerは、型安全性を中心に設計されたルーターです。ルートパラメータ、検索パラメータ、loader、router context、Linkなどが型推論され、TypeScript前提の開発で強い安心感があります。

優れている点

  • ルート定義から型が推論され、リンクやパラメータのミスを早期に見つけやすい。
  • 検索パラメータを状態として扱うAPIが強く、フィルタ、ページング、ソートのようなURL状態に向いている。
  • loader、preload、キャッシュ、stale-while-revalidate的なデータ取得体験を持つ。
  • TanStack Query、TanStack Store、TanStack Formなどの関連ライブラリと思想が揃っている。

注意点

React Routerより新しく、チームやプロジェクトによっては学習コストがあります。型安全な設計は強力ですが、そのぶんルート定義やジェネレータ、ファイルベースルーティングの考え方を理解する必要があります。

フレームワークとしての違い

観点 React Router TanStack Router / Start
フレームワーク化 Framework ModeでViteプラグイン、route module、SSRなどを扱う。 TanStack StartがTanStack Routerを土台にフルスタック機能を提供する。
データ取得 loader、clientLoader、action、useFetcher、revalidationが中心。 loader、preload、router cacheに加え、TanStack Queryとの連携が自然。
型安全性 Framework Modeで型生成はあるが、ルート全体の型安全DXは控えめ。 ルート、params、search、context、linksまで型安全に寄せる設計。
思想 Web標準、フォーム、loader/action、サーバーとの同期を重視。 TypeScript DX、URL状態、キャッシュ、TanStackエコシステムを重視。

ストア管理の観点

ここでいうストア管理は、すべてをReduxやZustandのようなグローバルストアに入れる話ではありません。Reactアプリでは、状態を大きく「URL状態」「サーバー状態」「UIローカル状態」「グローバルなクライアント状態」に分けると整理しやすくなります。

React Routerの場合

React Routerは公式ドキュメントでも、loader、action、useNavigation、useFetcher、URL search params、cookies、sessionsなどを使うことで、従来のクライアント状態管理の一部が不要になると説明しています。特にフォーム送信、送信中状態、送信後の再検証、ルートデータの同期はReact Router側に寄せられます。

一方で、React Router自体は汎用のクライアントストアではありません。複雑なクライアント状態、リアルタイム性の高いキャッシュ、複数画面で共有する細かなUI状態には、Zustand、Redux Toolkit、Jotai、TanStack Queryなどを併用する設計になります。

TanStack Routerの場合

TanStack RouterはURL状態、検索パラメータ、loader、preloadが強く、そこにTanStack Queryを組み合わせるとサーバー状態のキャッシュ、再取得、無効化、楽観更新まで一貫して扱いやすくなります。TanStack公式にも外部キャッシュとしてTanStack Queryを使う案内があります。

さらに、クライアント状態にはTanStack Store、フォームにはTanStack Formという選択肢があります。つまり、ルーティング、サーバー状態、フォーム、クライアントストアをTanStack系で揃えられるのが大きな特徴です。

どちらが優れているか

絶対的な勝敗というより、プロジェクトの重視点で選ぶのがよいです。

  • 実績、情報量、Web標準寄りのフォーム処理、Remix的なデータフローを重視するならReact Router。
  • TypeScriptの型安全性、URL search params、TanStack Queryとの統合、DXを重視するならTanStack Router。
  • 既存のReact Router資産があるなら、無理に移行せずFramework ModeやData Modeを活かす。
  • 新規TypeScriptアプリで検索条件やフィルタが多く、URLを状態として強く扱いたいならTanStack Routerが有力。
  • サーバー状態管理を中心に設計するなら、TanStack Router + TanStack Queryの組み合わせがかなり強い。

要点

React Routerは「実績あるReact標準ルーターがフレームワーク化したもの」、TanStack Routerは「型安全なルーティングとURL状態管理を中心に、TanStackエコシステムへ接続するもの」と考えると整理しやすいです。ストア管理まで含めた新規開発ではTanStack Router + TanStack Queryが強く、既存資産やWeb標準寄りのフレームワーク体験ではReact Routerが堅実です。
