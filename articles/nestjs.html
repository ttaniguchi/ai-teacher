NestJSの特徴と使い方

作成日: 2026年5月21日

NestJSは、Node.jsで構造化されたサーバーサイドアプリケーションを作るためのフレームワークです。TypeScript、DI、モジュール、Controller、Serviceを前提に、ExpressやFastifyの上で保守しやすいAPIサーバーを組み立てられます。

簡潔なQ&A

Q. NestJSとは何ですか？
A. Node.js上で動くサーバーサイドフレームワークです。ExpressやFastifyを土台にしつつ、TypeScript、依存性注入、モジュール分割、デコレータによるルーティングを標準的な設計として提供します。
Q. 何が便利ですか？
A. ControllerとServiceを分け、Module単位で機能を整理できるため、中規模以上のAPIサーバーやチーム開発で構成が散らかりにくくなります。
Q. どうやって使い始めますか？
A. Nest CLIでプロジェクトを作成し、Controller、Service、Moduleを追加します。HTTPリクエストはControllerで受け、処理の本体はServiceへ置くのが基本です。

NestJSの位置づけ

NestJSは、Node.jsでバックエンドを作るときのアプリケーション構造を強く用意してくれるフレームワークです。ExpressだけでもAPIは作れますが、ファイル構成、依存関係、バリデーション、認証、例外処理などの設計は開発者側に任されがちです。NestJSはそこに、AngularやSpring Bootに近い構造化された開発体験を持ち込みます。

内部のHTTPサーバーとしては、標準ではExpressを使います。必要に応じてFastifyへ切り替えられるため、NestJSは「Expressの代替」というより、「ExpressやFastifyの上にアプリケーション設計の型を載せるもの」と捉えると理解しやすいです。

主な特徴

TypeScript中心の設計

NestJSはTypeScriptとの相性を前提に作られています。DTO、Service、Controller、Moduleに型を付けながら実装できるため、APIの入力や返却値、依存関係を明確にしやすくなります。

Moduleによる分割

機能ごとにModuleを作り、その中にControllerやServiceを登録します。たとえばユーザー管理ならUsersModule、認証ならAuthModuleのように分けることで、アプリ全体の責務を追いやすくなります。

@Module({
  controllers: [UsersController],
  providers: [UsersService],
})
export class UsersModule {}

ControllerとServiceの分離

ControllerはHTTPリクエストの入口です。URL、HTTPメソッド、パラメータを受け取り、実際の処理はServiceへ委譲します。Serviceはビジネスロジックやデータ取得を担当します。

@Controller('users')
export class UsersController {
  constructor(private readonly usersService: UsersService) {}

  @Get()
  findAll() {
    return this.usersService.findAll();
  }
}

依存性注入

@Injectable()を付けたクラスは、NestJSのDIコンテナからControllerなどへ注入できます。クラス同士を直接生成しないため、テスト時の差し替えや責務分離がしやすくなります。

@Injectable()
export class UsersService {
  findAll() {
    return [
      { id: 1, name: 'Alice' },
      { id: 2, name: 'Bob' },
    ];
  }
}

基本的な使い方

まずNest CLIを使ってプロジェクトを作成します。

npm i -g @nestjs/cli
nest new my-app
cd my-app
npm run start:dev

機能を追加するときは、CLIでModule、Controller、Serviceを生成できます。

nest g module users
nest g controller users
nest g service users

典型的な構成は次のようになります。

src/
  main.ts
  app.module.ts
  users/
    users.module.ts
    users.controller.ts
    users.service.ts

最小のAPI例

次の例では、GET /usersへアクセスするとユーザー一覧が返ります。

// users.service.ts
@Injectable()
export class UsersService {
  findAll() {
    return [
      { id: 1, name: 'Alice' },
      { id: 2, name: 'Bob' },
    ];
  }
}

// users.controller.ts
@Controller('users')
export class UsersController {
  constructor(private readonly usersService: UsersService) {}

  @Get()
  findAll() {
    return this.usersService.findAll();
  }
}

実務でよく使う機能

機能 役割 使いどころ
Pipe 入力値の変換やバリデーションを行う。 DTOと組み合わせて、リクエストボディやクエリを検証する。
Guard リクエストを通すかどうかを判定する。 認証済みユーザーだけ通す、権限ごとに制御する。
Interceptor 処理の前後に共通処理を挟む。 レスポンス整形、ログ、計測、キャッシュなど。
Exception Filter 例外をHTTPレスポンスへ変換する。 エラー形式を統一する。
Middleware ルート到達前に処理を実行する。 リクエストログ、ヘッダー処理、簡単な前処理。

向いている場面と注意点

NestJSは、中規模以上のAPIサーバー、チーム開発、長期運用するバックエンド、認証やDB連携を含む業務アプリに向いています。構成の型があるため、開発者が増えてもコードの置き場所や責務をそろえやすいからです。

一方で、小さなプロトタイプや数本のAPIだけなら、ExpressやFastifyを直接使うほうが軽く済むことがあります。NestJSはModule、DI、デコレータ、ライフサイクルなどを理解する必要があるため、最初の学習コストはやや高めです。

要点

NestJSは、Node.jsで保守しやすいバックエンドを作るための構造化フレームワークです。Controllerでリクエストを受け、Serviceに処理を置き、Moduleで機能をまとめる、という基本形を覚えると全体像をつかみやすくなります。小規模用途では少し重いですが、APIが増えるプロジェクトでは設計の足場として有効です。
