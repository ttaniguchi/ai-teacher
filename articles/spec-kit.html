Spec Kitとは？概要と簡潔な使い方

作成日: 2026年10月19日

Spec Kitは、AIによる開発を「仕様 → 設計 → タスク → 実装 → 検証」の順に進めるためのGitHubのオープンソースツールキットです。作りたいものを文章で明確にし、仕様と実装を照らし合わせながら開発を進めます。

簡潔なQ&A

Q. Spec Kitは何をするものですか？
A. AIコーディングエージェントに、仕様書・設計・タスク一覧を作る手順とテンプレートを提供し、それらに基づく実装と確認を支援します。
Q. 単独でコードを生成するAIですか？
A. 実際の生成・編集はGitHub CopilotやClaude Codeなどの連携するAIエージェントが行います。Spec Kitは、その作業の進め方を整える役割です。
Q. 最初に何をすればよいですか？
A. CLIでプロジェクトを初期化し、AIのチャットで方針、仕様、設計、タスク化、実装、完了確認の各工程を一つずつ実行します。

確認日: 2026年10月19日。以下は公式ドキュメントに基づく説明です。コマンド表記は導入バージョンやエージェントのモードによって異なります。

概要：仕様を開発の基準として残す

中心となるのは仕様駆動開発（Spec-Driven Development、SDD）です。「何を作るか」「どう作るか」「何を実行するか」を文書として整理し、実装後もその文書とコードを照合します。Spec Kitは再利用できるテンプレートと構造化された工程を提供します。

文書役割ToDoアプリの例
spec.md何を・なぜ作るかタスクを追加・完了・削除でき、再読み込みしても残る
plan.md技術選択と設計ReactとTypeScriptを使い、localStorageに保存する
tasks.md依存関係を踏まえた作業一覧保存処理、一覧画面、操作、テストを順に実装する

SDDは標準で利用できます。バグ修正やアイデア評価の工程も、必要に応じて追加する拡張として用意されています。詳細は公式リポジトリを参照してください。

1. インストールして初期化する

Python 3.11以上、uv、対応するAIコーディングエージェントを用意します。次はGitHub Copilotを使う新規プロジェクトの例です。ここはターミナルで実行します。

uv tool install specify-cli
specify version
specify init my-app --integration copilot
cd my-app

specify-cliは公式のPyPI配布パッケージです。GitHubのリリースタグを指定するソースインストールも公式に案内されています。既存プロジェクトにはspecify init --hereで導入できますが、既存ファイルとのマージがあるため、変更をコミットまたはバックアップしてから行います。公式インストールガイド

2. AIのチャットで工程を進める

プロジェクト内でAIエージェントを起動します。以下は公式クイックスタートのGitHub Copilot・skillsモードの表記です。ターミナルにまとめて貼り付けず、チャットで一つずつ入力し、結果を確認してから次へ進みます。

方針を決める：プロジェクトの最初に実行

/speckit-constitution 保守性を優先し、主要機能にテストを用意する。

後続の工程で守る原則を定義します。機能ごとの仕様を作る前に、プロジェクト全体の基準をそろえます。

仕様を作る：何を実現したいかを書く

/speckit-specify 個人用ToDoアプリを作る。タスクを追加・完了・削除でき、再読み込み後も内容を保持する。ログインと共有機能は不要。

ここでは目的、利用者、期待する動作、対象範囲を伝えます。技術選択は次の設計段階に分けます。

設計する：使う技術と構成を伝える

/speckit-plan TypeScriptとReactを使い、データはlocalStorageに保存する。バックエンドは設けない。

タスク化・実装・完了確認を順に行う

  1. /speckit-tasks：設計から作業一覧を作る。抜けや作業順を確認する。
  2. /speckit-implement：タスクに沿って実装する。
  3. /speckit-converge：仕様・設計・タスクとコードを照合する。

完了確認で不足が見つかると追加タスクが記録されます。その場合は実装と完了確認を繰り返し、最後に変更内容とテスト結果をレビューします。公式クイックスタート

必要に応じて追加する確認工程

  • /speckit-clarify：仕様作成後・設計前に、曖昧な点を質問で解消する。
  • /speckit-checklist：設計後・タスク化前に、要件の明確さや網羅性を確認するチェックリストを作る。
  • /speckit-analyze：タスク化後・実装前に、仕様・設計・タスク間の矛盾や不足を読み取り専用で点検する。

チェックリストは要件の品質を確認するためのもので、実装完了やテスト合格を意味しません。AIが出力した文書についても、人が意図に合っているか確認します。

使いどころと注意点

工程の性質から、複数の要件を整理したい機能追加や、設計の意図を後から追いたい開発に向いていると考えられます。一方、数行の修正では文書を整える負担が大きくなる場合があります。最初は小さな機能を一つ選ぶと、工程の役割を理解しやすくなります。

仕様が誤っていれば、その仕様に沿った実装も目的から外れます。各工程の出力確認と、動作テスト・コードレビューを組み合わせて使います。また、資料によっては/speckit.specifyなど別の呼び出し表記が使われています。利用するエージェントとモードに合う表記を公式資料で確認してください。

要点

Spec Kitは、AI開発に仕様と工程を持たせるツールキットです。まず方針を決め、「仕様 → 設計 → タスク → 実装 → 完了確認」を一つずつ進めます。仕様では目的と動作、設計では技術と構成を伝えるのが基本です。
