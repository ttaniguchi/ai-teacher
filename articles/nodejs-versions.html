Node.jsの現在の安定版と前後バージョンの違い

作成日: 2026年6月2日

2026年5月19日時点では、本番運用で選ぶ安定版はNode.js 24 LTSです。最新のCurrentリリースはNode.js 26ですが、LTS化までは検証用・先行評価用として扱うのが安全です。

簡潔なQ&A

Q. 現在の安定バージョンは？
A. 2026年5月19日時点の本番向け安定版はNode.js 24 LTSです。公式サイトでは最新LTSとしてv24.15.0、最新リリースとしてv26.1.0が示されています。
Q. ひとつ前の安定版との差異は？
A. ひとつ前のLTS系はNode.js 22です。Node.js 24ではV8 13.6、npm 11、URLPatternのグローバル化、Permission Modelの改善、AsyncLocalStorageの実装変更、Undici 7などが入り、より新しいWeb APIと実行基盤に近づいています。
Q. 次バージョンは何が優れている？
A. Node.js 26 CurrentではTemporal APIが標準で有効化され、V8 14.6、Undici 8などが入っています。日付時刻処理や新しいJavaScript機能の面では優位ですが、LTS化前なので本番採用は慎重に検証する段階です。
Q. Node.jsの奇数バージョンは今後もLTSにならないのか？
A. これまでは奇数バージョンが短期Current、偶数バージョンがLTS候補という運用でした。ただしNode.js 27以降は年次リリースへ移行し、すべてのメジャーバージョンがCurrent期間を経てLTSへ進む方針に変わります。

Node.jsのリリースの考え方

Node.jsには、Current、Active LTS、Maintenance LTSという段階があります。新しいメジャーバージョンはまずCurrentとして提供され、一定期間の検証を経てLTSになります。本番アプリケーションでは、公式にもActive LTSまたはMaintenance LTSを使うことが推奨されています。

2026年5月19日時点では、Node.js 24がActive LTS、Node.js 22がMaintenance LTS、Node.js 26がCurrentです。Node.js 25はMaintenance扱いで、2026年6月1日にサポート終了予定の短命な奇数バージョンです。

奇数・偶数リリース方針の変更

従来のNode.jsでは、偶数メジャーバージョンがLTSへ進み、奇数メジャーバージョンは短期のCurrentとして使われたあとLTSにならず終了する、という運用でした。たとえばNode.js 23や25は、次の偶数バージョンへ移るまでの短期評価ラインとして扱われてきました。

ただし公式リリース説明では、Node.js 27以降は年次リリースへ移行し、各メジャーバージョンがCurrent期間を経てLTSへ進む方針が示されています。つまり「奇数だからLTSにならない」という覚え方は、Node.js 26までの世代には有効ですが、Node.js 27以降には当てはまりません。

実務上は、バージョン番号の奇数・偶数だけで判断するより、公式のRelease Scheduleでその時点のStatusがActive LTS、Maintenance LTS、Current、EOLのどれかを見るのが安全です。

現在の安定版: Node.js 24 LTS

現在の安定版として見るべき中心はNode.js 24 LTS、コードネームKryptonです。2025年5月6日に初回リリースされ、2025年10月28日にLTSへ入りました。Active LTSは2026年10月20日まで、その後Maintenanceに移り、EOLは2028年4月30日予定です。

Node.js 24の主な特徴

  • V8 JavaScriptエンジンが13.6へ更新。
  • npm 11を同梱。
  • URLPatternがグローバルで利用可能。
  • Permission Modelのフラグが--experimental-permissionから--permissionへ変更。
  • AsyncLocalStorageがAsyncContextFrameを標準実装として使うようになった。
  • Undici 7によりHTTPクライアント基盤が更新。
  • テストランナーがサブテストの完了を自動で待つなど、テスト体験が改善。

さらにv24.15.0では、require(esm)とmodule compile cacheがstable扱いになり、SQLite関連APIがrelease candidateになるなど、LTS内でも実用上の改善が進んでいます。

前の安定版: Node.js 22 LTSとの差異

Node.js 22 LTSはコードネームJodで、現在はMaintenance LTSです。Node.js 22自体も、WebSocketの標準有効化、node --run、fs.glob、同期ESMグラフのrequire()対応など、十分に近代的な機能を持っています。

Node.js 24との差分は、単一の巨大機能というより、実行基盤・Web API・セキュリティ境界・HTTP基盤の更新です。Node.js 22を使っているプロジェクトは即座に危険というわけではありませんが、新規開発や次の長期運用を考えるならNode.js 24へ寄せるほうが自然です。

観点 Node.js 22 LTS Node.js 24 LTS
ステータス Maintenance LTS。EOLは2027年4月30日予定。 Active LTS。EOLは2028年4月30日予定。
JavaScriptエンジン V8 12.4系で登場。 V8 13.6系で登場。新しいJavaScript機能を多く含む。
Web API WebSocket clientが標準で有効化。 URLPatternがグローバル化し、よりWeb標準APIに近づいた。
セキュリティ境界 Permission Modelはまだ実験的な印象が強い。 --permissionへ改名され、Permission Modelの安定化が進んだ。
運用判断 既存運用では継続可能だが、Maintenance期。 新規・更新の第一候補。

次バージョン: Node.js 26 Currentの優位性

Node.js 26は2026年5月5日にCurrentとしてリリースされ、2026年10月28日にLTS入りする予定です。2026年5月19日時点では最新リリースがv26.1.0ですが、本番向け安定版ではなく、次のLTS候補として評価する段階です。

Node.js 26の主な優位性

  • Temporal APIが標準で有効化され、従来のDateより堅牢な日付時刻処理が可能になる。
  • V8 14.6により、より新しいJavaScript機能やエンジン改善を利用できる。
  • Undici 8により、Node.jsのHTTPクライアント基盤がさらに更新される。
  • v26.1.0では実験的なnode:ffi、crypto.randomUUIDv7()、テストランナー改善などが追加されている。

注意点

Node.js 26はCurrentなので、ライブラリ作者やアプリ開発者が互換性を確認するための期間にあります。古いAPIの削除やランタイム非推奨化も含まれるため、ネイティブアドオン、古いHTTP/stream API、ビルド環境に依存しているプロジェクトでは事前検証が必要です。

実務での選び方

  • 新規プロジェクト、本番運用、学習用途の標準はNode.js 24 LTS。
  • 既存プロジェクトがNode.js 22 LTSなら、急ぎではなくてもNode.js 24への移行計画を作る。
  • Node.js 20以前はEOLまたはEOL済みなので、セキュリティ上は避ける。
  • Node.js 26は、次期LTSに備えた検証環境、ライブラリ互換性チェック、新機能評価に使う。
  • 本番投入はNode.js 26がLTS化してから、依存ライブラリとCIを通して判断する。

要点

2026年5月19日時点では、安定版としてNode.js 24 LTSを選ぶのが最も堅実です。Node.js 22 LTSはまだ保守されていますがMaintenance期であり、Node.js 26 CurrentはTemporalやV8 14.6など次世代の利点がある一方、本番標準にするにはLTS化を待つのが安全です。
