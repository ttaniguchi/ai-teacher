JavaScript / 日付時刻

Temporal APIとは何か

Temporal APIは、JavaScriptの古いDate APIが抱えていた曖昧さを解消するための新しい日付時刻APIです。Node.js 26では標準で有効化され、時点、日付、時刻、タイムゾーン付き日時、期間を明確に分けて扱えます。

簡潔なQ&A

Q. Temporal APIとは何？
A. JavaScriptの新しい日付時刻APIです。従来のDateよりも、タイムゾーン、カレンダー、期間、日付だけ、時刻だけ、といった概念を明確に扱えるように設計されています。
Q. なぜDateでは足りないのか？
A. Dateは内部的には単一のタイムスタンプですが、入出力ではローカルタイムゾーンが絡みやすく、日付だけを表したい場合やタイムゾーンを明示したい場合に間違いが起きやすいからです。
Q. Node.js 26で何が変わる？
A. Node.js 26ではTemporal APIが標準で有効化されます。これにより、ライブラリなしでより安全な日付時刻処理を試せるようになります。ただしNode.js 26自体はLTS化前のCurrentなので、本番利用は検証が必要です。

Temporalが解決する問題

JavaScriptのDateは、長年使われてきた一方で、設計上の難しさがあります。Dateは「ある瞬間」をミリ秒のタイムスタンプとして持ちますが、文字列の解釈や表示では実行環境のローカルタイムゾーンが関わります。そのため、単なる誕生日、予約日、締切日、現地時刻、UTCの瞬間を同じ型で扱うことになり、バグの温床になります。

Temporalはこの問題を、用途ごとに型を分けることで解決しようとします。「絶対的な瞬間」と「カレンダー上の日付」と「タイムゾーン付きの日時」を別物として扱うため、コードを読む側にも意図が伝わりやすくなります。

主要な型

型 表すもの 使いどころ
Temporal.Instant タイムゾーンに依存しない絶対的な時点。 ログ時刻、作成日時、イベント発生時刻など。
Temporal.ZonedDateTime 日時とタイムゾーンを組み合わせた値。 東京の午前9時、ニューヨークの会議時刻など。
Temporal.PlainDateTime タイムゾーンなしの日付と時刻。 タイムゾーン未確定の予定入力など。
Temporal.PlainDate 日付だけ。 誕生日、締切日、営業日、記念日など。
Temporal.PlainTime 時刻だけ。 毎日9:00開始、店舗営業時間など。
Temporal.Duration 期間や差分。 3日後、90分、1か月間など。

Dateとの考え方の違い

Dateでは、たとえば「2026-05-19」という日付だけを扱いたい場合でも、実際には時刻とタイムゾーンが絡んだ値になりがちです。Temporalでは、日付だけならTemporal.PlainDateを使います。これにより「この値はタイムゾーン変換されるべきではない」という意図が型に表れます。

逆に、サーバーに保存する作成日時やログ時刻のように、世界中で同じ瞬間を指したい場合はTemporal.Instantが向いています。ユーザーの地域で表示したいときだけ、タイムゾーンを指定してZonedDateTimeへ変換します。

簡単な例

// 日付だけを表す
const deadline = Temporal.PlainDate.from("2026-05-19");

// 絶対的な現在時刻
const now = Temporal.Now.instant();

// 東京時間の現在日時
const tokyoNow = Temporal.Now.zonedDateTimeISO("Asia/Tokyo");

// 3日後の日付
const threeDaysLater = deadline.add({ days: 3 });

このように、Temporalでは「何を表したいのか」を型名で選びます。日付計算もaddやsubtractのような明示的なメソッドで行えるため、ミリ秒計算に頼るより読みやすくなります。

Temporalが特に効く場面

  • 複数タイムゾーンをまたぐ予約、配送、会議スケジュール。
  • 誕生日や締切日のように「日付だけ」が重要なデータ。
  • 夏時間の切り替わりで時刻が存在しない、または重複する地域を扱う処理。
  • ログや監査証跡のように、世界中で同じ瞬間を正確に保存したい処理。
  • 期間計算を30 * 24 * 60 * 60 * 1000のようなミリ秒計算から卒業したい場合。

注意点

Temporalは強力ですが、Dateを機械的に置き換えるだけではうまくいきません。まず「この値は瞬間なのか、日付なのか、タイムゾーン付き日時なのか」を決める必要があります。この設計判断がTemporalの肝です。

また、Node.js 26では標準で有効化されていますが、ブラウザや実行環境によって対応状況は異なります。フロントエンドで使う場合は、対象ブラウザの対応状況やpolyfillの必要性を確認する必要があります。

要点

Temporal APIは、JavaScriptの日付時刻処理を「曖昧なDateひとつ」から「用途別の明確な型」へ分解するためのAPIです。Node.js 26の大きな価値は、Temporalによってタイムゾーンや日付だけの処理を標準APIで安全に扱えるようになる点にあります。
